# daily-log — 日次作業ログの書き出し（Layer 1）

セッション終了時に、今日の作業内容を `layer1_logs/` に生ログとして記録します。

## 実行手順

### Step 1: 今日の会話を振り返る

今日の会話全体を読み返し、以下を把握する:

- 何をやったか（作業内容・ツール操作・ファイル作成など）
- どんな判断をしたか（重要な意思決定）
- AI の出力に修正が必要だった場面はあったか
- 次回やること・残った宿題

### Step 2: ファイル名を決める

形式: `layer1_logs/YYYY-MM-DD_作業名.md`

- 日付は今日の日付（`YYYY-MM-DD`）
- 作業名は今日のメインテーマを 2〜5 文字で表現
- 例: `layer1_logs/2026-04-04_旬DB設計.md`

### Step 3: ログファイルを作成する

以下のフォーマットで書く:

```markdown
---
title: <作業名>
type: log
created: YYYY-MM-DD
---

# YYYY-MM-DD 作業名

## 今日やったこと
- （箇条書きで簡潔に。完了したものは ✅ をつけると見やすい）

## 決めたこと・気づいたこと
- （重要な判断基準・方針・発見。未来の自分/Claude が読んでも分かる粒度で）

## AI とのズレ・修正したこと
- （Claude の出力で違和感があった点、修正したこと。なければ「なし」）

## 次回やること
- （続きの作業・宿題・確認事項）

## 関連ファイル
- （このセッションで作成・編集したファイルのパス）
```

### Step 4: 昇格の判断と提案

ログを書きながら、以下に該当するものがあれば提案する:

| 状況 | 昇格先 | 判断基準 |
|------|--------|---------|
| 同じ作業が 2〜3 回登場した | `layer2_skills/` | 手順書としてスキル化 |
| 重要な気づきや失敗の教訓 | `layer2_learnings/` | 将来の意思決定に役立つ |
| AI とのズレが繰り返されている | `CLAUDE.md` の作業ルール | 同じミスを繰り返さない |

### Step 5: git 保存（git を使う場合）

ログ作成後、git を使っているなら次を実行してコミットする:

```bash
cd "<VAULT_DIR>" && \
LOGFILE="layer1_logs/YYYY-MM-DD_作業名.md" && \
git add "$LOGFILE" && \
git commit -m "log: $(basename "$LOGFILE" .md | sed 's/_/ /')" && \
git pull --rebase && git push
```

- `<VAULT_DIR>` は vault の絶対パスに置き換える
- push が失敗しても commit は残る。次回のセッション終了フックで再送される
- 複数端末で同じ vault を使う場合は、書いた本人の端末が真っ先に commit すること（同期競合を防ぐ）
